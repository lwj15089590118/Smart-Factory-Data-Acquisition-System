# 项目总结（第一人称）

这个项目是我为了打通"感知层 → 网络 → 应用"完整物联网链路而做的嵌入式数据采集系统。先说清楚定位：**项目分两部分——STM32 固件是按真实硬件完整设计的工程代码（我目前没有实物，未经编译烧录与真机验证）；Python 上位机是真实开发、真实运行、带 35 项自动化测试的实测部分**。我在 README 里对这个口径做了明确定位声明，面试时我也会主动讲清楚这条边界。

固件设计上，我基于 STM32F103C8T6 完成了采集节点的全部核心逻辑：DHT11 单总线时序（含位判定窗口对微秒级延时的依赖与容错设计）、ACS712 电流与分压电压的 ADC 采集、中值滤波加滑动平均加开机零点自校准的抗干扰链路、OLED 本地显示、按键阈值设置与 Flash 掉电保存、蜂鸣器/继电器报警输出，以及 ESP8266 AT 指令驱动的 MQTT 状态机——QoS1 发布、心跳保活、LWT 遗嘱掉线感知、断线 30 秒周期重连。针对嵌入式采集系统最高频的三类问题（数据跳变、通信断连、阈值误报），我在《调试问题对策手册》里按"现象→排查→根因→措施"逐条推演了排查方法学与设计对策（滤波参数、独立供电加储能电容、三次确认加迟滞回差），这些对策全部落实在固件代码里，等真机到位即可按手册逐条对照验证。

上位机是项目的实测部分：我用 Python 开发了 Flask + paho-mqtt + pandas + ECharts 的监控看板，实时曲线、仪表盘、报警事件表、统计报表与 CSV 导出可用；并写了一套 35 项 pytest 测试，其中协议一致性测试用纯 Python 复刻了固件侧的报文解析器做两端互锁回放——固件怎么解析，上位机就怎么断言，两端字段与阈值语义被测试锁死。这让我在没有硬件的条件下，依然把"上下行协议正确性"验证到了可回归的程度。

这个项目给我最大的收获，是学会了在资源受限的嵌入式语境下做工程取舍：AT 指令流的转义坑、QoS1 重复投递的去重口径、NaN 在统计接口的边界行为，都是具体而真实的工程问题。我也很清楚自己的短板：缺少真机调试经验——示波器看波形、万用表核线、EMI 排查这些只能上实物才能练。所以我的下一步很具体：补 Keil 工程骨架入库、购置最小系统套件（约百元级），把《对策手册》里的每一条推演变成真实调试记录。在此之前，我不会把设计说成实测。
